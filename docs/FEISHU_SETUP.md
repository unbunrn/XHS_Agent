# 飞书手机审批接入
适用项目：D:\Dev\Projects\bot。核对日期：2026-11-06 +08:00。
当前状态（2026-11-06 17:36 +08:00）：应用已创建，测试通知已送达，本人私聊事件已实际收到；完整图文审批彩排已于 2026-11-06 17:48 +08:00 完成，批准入库并回执，未发布作品。

## 第一步：创建应用
在电脑打开 https://open.feishu.cn/app ，登录自己的飞书账号，创建“企业自建应用”（不要选群聊里的 Webhook 自定义机器人）。
建议名称“AI 运营助手”，描述“把 AI 选题和完整图文发给本人审批”，添加图标，添加“机器人”能力。
如果你所在组织要求管理员审核，按该组织流程处理；个人账号界面请以开放平台实际提示为准。

## 第二步：最少权限
在“权限管理”选择应用身份权限：
- im:message:send_as_bot：以应用身份发消息。
- im:message.p2p_msg:readonly：接收你发给机器人的单聊消息。
- im:resource：上传作品图片。
本版本不需要读取全员通讯录或所有群聊。审批走你与机器人的私聊。

## 第三步：只在本机填写凭据
在“凭证与基础信息”找到 App ID 和 App Secret。
打开项目 config/secrets.toml，在现有 DeepSeek 配置下面追加以下字段，替换双引号中的占位文字，保留原有内容：
```toml
lark_app_id = "你的 App ID"
lark_app_secret = "你的 App Secret"
lark_owner_open_id = "你在此应用下的 ou_ 开头标识"
```
不要把这些值贴到聊天、文档或截图中。不要用群聊 oc_ 标识代替 owner_open_id。

获取自己的 open_id：
在飞书 API 调试台选择“刚刚创建的应用”，找带 user_id_type/member_id_type 的接口，选择 open_id，使用“快速复制 open_id / 复制成员 ID”从成员选择器选自己。
open_id 与应用绑定；别从另一个应用复制。这里仅选取标识，不需要执行发送消息接口或额外申请通讯录权限。
官方错误码文档有该操作说明：https://open.feishu.cn/document/server-docs/api-call-guide/generic-error-code

## 第四步：建立长连接，再保存事件
先完成本机依赖安装与配置检查。项目根目录执行：
```powershell
.\.venv\Scripts\python.exe -m bot doctor
.\.venv\Scripts\python.exe -m bot lark
```
保持第二条命令运行；它负责接收审批，不会自行生成或发布作品。
在开放平台进入“事件与回调 → 事件配置”，选择“使用长连接接收事件”。本地客户端在线时才能保存。
点击“添加事件”，勾选“接收消息 v2.0”：im.message.receive_v1 并确认添加。检查“已添加事件”表格确实出现该事件：只选择长连接、表格仍为空时，不会推送消息事件。添加后继续第五步发布新版本；开通消息权限不能代替事件订阅。

## 第五步：发布应用并限定可用范围
在“版本管理与发布”创建版本，将可用范围限定为你本人，发布。组织账号如需管理员审核，等待审核通过。
用手机飞书搜索应用名称，进入机器人私聊；不要在群里审批。
确认手机飞书通知已开启。

## 第六步：先做审批彩排
凭据配置好后告诉当前开发会话“飞书已配置”，再一起完成真实通知测试。
彩排仍保持真实发布开关关闭。需要确认：手机收到完整正文和全部图片；只有你本人私聊命令生效；修改后生成新审批；重复消息不会重复发布。
收到真实待审批作品后，命令示例：
- 批准 XH-ABC123
- 拒绝 XH-ABC123
- 修改 XH-ABC123 标题更克制，补充适用人群
示例编号不可直接使用，需替换成收到的实际审批码。

审批绑定具体版本和图片。内容修改、审批过期、图片未完整送达都会阻止发布。
首次真实发帖仍需你审核具体作品，并完成小红书账号绑定与发布通道验证。

## 运转条件与边界
电脑必须开机、联网，后台进程保持运行；飞书长连接无需公网域名或内网穿透。
当前不保证关机后继续运行，也没有安装开机自动启动。
真实发布后的回执如果不含帖子标识，将停在“结果待核对”，不会自动重发。
小红书为第三方社区桥接方案，需要单独扫码绑定，本次尚未接入真实账号。
