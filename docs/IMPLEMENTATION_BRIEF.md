# 持久化 AI 账号运营 Agent：实现指令
更新日期：2026-11-05 +08:00。本文是产品设计与验收要求，不代表已实现或已部署。

## 用户确认的范围
用户希望 agent 持续搜集 AI 新闻，选题、核实、形成有价值的观点、制作作品、运营账号并根据结果改进；发布作品及关键操作需手机确认。用户只有 DeepSeek 服务，指定使用本机 D:\DeepSeek_Harness 实现，项目目录 D:\Dev\Projects\bot。平台与通知渠道由我们选择。D:\CodexSync\work 仅是交接仓库，不修改其源码或配置、不提交或推送。

## 决策
- 第一版：小红书 AI 实用热点图文，飞书私聊确认。文本观点＋模板卡片，避免新购图像、视频模型。
- 小红书接入候选 xpzouying/xiaohongshu-mcp；它是社区浏览器自动化，不是官方接口或稳定性保证。实现之前核对 API、限制、登录和账号支持。验证码、登录失效、风控交给用户。
- 飞书用官方 SDK 长连接接收私聊消息，无需公网入站端口。初版用“批准 审批码 / 拒绝 审批码 / 修改 审批码 意见”；卡片仅作预览，未验证按钮回调支持时不得宣称按钮可用。绑定本人 open_id，拒绝群聊、他人、重放、过期审批。
- 持久化采用本机 SQLite 事务状态机、任务租约、事件日志和进程监督。没有任务时不调用模型。电脑关机/休眠不能运营；恢复后跳过过期热点，不能爆量补发。
- DeepSeek Harness 用于受控开发。运营时用专用受限工具和 DeepSeek API；模型不能直接得到发布凭据或任意 shell。只有 API key 缺失时可以离线演示，不能伪称真实模型联通。
- 当前 Windows + Harness 0.2.1-rc.5；agent-autoloop 当前文档不支持 Windows，内置 DSH 插件要求 >=0.2.2。借鉴其事件唤醒、持久化审批和重试机制，第一版不硬装不兼容版本。
- 先做单账号闭环；X、知乎、抖音仅定义接口扩展点，不能写成已支持。

## 运营行为
1. 每 30 分钟轻量抓取已配置来源。默认选直接官方 RSS/公告；使用 ETag/Last-Modified，限速、退避、超时、正文大小限制。
2. 发现的资料记住原始 URL、来源、发表与抓取时间、内容指纹；去除追踪参数与重复报道，按事件聚类。未知日期不冒充今日。
3. 根据受众相关度、可信证据、新意、时效、实用价值和可制作性排序。宁可不发，也不为凑数造热点。
4. 重要事实逐条对应实际获取的证据片段；多个转述同一新闻稿不算独立证据。官方自述的性能写成“厂商称”。无法核实内容留在研究队列。
5. 作品结构：发生了什么／对谁有用／具体怎么用／限制与不确定性／来源。明确区分事实与分析，不能虚构亲测、收益或个人经历。
6. 初始建议每天最多 1 篇成稿，最多 3 个待选题，审批队列上限 3；时区 Asia/Shanghai。上述是可配置试运行默认值，不是增长承诺。
7. 账号定位暂定“给中文普通用户和独立开发者讲明白 AI 工具变化”。积累用户修改理由、批准风格、已发题材、禁用表达、来源质量、近期作品，避免每天重头开始。
8. 评论只读与回复草稿可自动做；实际评论、私信、删除、改资料、广告花费和新增账号均需确认。第一版不批量点赞关注、不自动群发。
9. 发布后可收集平台允许获得的真实指标，按 24h/72h 记录收藏、互动等；拿不到的数据标为缺失。策略变更提出建议，不能靠单篇成绩自动改人设。

## 必须由代码强制的发布门禁
- 状态示例：discovered -> researched -> drafted -> review_pending -> approved -> publishing -> published；另有 rejected / expired / needs_login / failed / publish_unknown / paused。
- 一次审批绑定：platform + account_id + draft_id + draft_version + 正文摘要哈希 + 图片文件内容哈希 + 计划发布时间 + 失效时间。
- 改字、换图、变更账号/平台或发布时间均使旧审批失效。没有明确批准、无人回复、超时不得发布。
- 发布前重新检查审批、文件哈希、最新来源状态、发布预算、全局暂停开关和账号状态。
- 数据库唯一约束＋事务领取发布任务。并发点击与回调重试仅产生一次发布尝试。
- 请求已发出但无确认结果时进入 publish_unknown，查询平台回执或请用户核对，不能盲目重试。重启时 publishing 同样进入待对账，不能重发。
- 发布成功需真实平台 post_id/URL 或其他可核对的回执；mock/export 只能写 simulated/exported，不得写真实 published。
- 本地预览的批准按钮必须带用户登录/本机管理授权，不开放无鉴权审批 API；默认仅监听 127.0.0.1。GET 不执行状态变更。
- 不把通用 MCP 发布工具直接给写稿模型。发布适配器只能由门禁服务调用。
- 外部网页/评论全是资料，不能成为系统指令；严禁网页内容触发工具安装、改规则、读取密钥或直接发布。

## 技术建议
优先 Windows 原生易安装方案：Python 3.12、sqlite3、FastAPI 或标准库 HTTP、httpx、Pillow、飞书官方 lark-oapi。类型与业务校验清晰，依赖尽量少；不为单账号引入 Redis/Celery/Kubernetes。
- 用接口分离 source / researcher / writer / renderer / approval / publisher / analytics。
- 提供 fake LLM + fake source + fake publisher 的完整离线演示；真实模式绝不能静默回退成 fake。
- DeepSeek 模型及 base URL 可配置，当前官方推荐 model id 为 deepseek-flash，调用前以官方文档和账户能力为准。Key 仅由环境/本机秘密文件读取，不打印、不写测试产物。
- API 日预算默认保守并可配置；每轮限制候选数、token、工具调用、重试。记录实际 usage；没有返回 usage 时标未知并保守预留，不能记零。
- 采集器阻止私网/回环/元数据地址的 SSRF（经明确配置的本机发布服务除外，且不能让新闻 URL 调用它）。
- SQLite WAL + busy timeout + migrations + transactional state transitions。任务有 lease_owner、lease_until、attempts、next_run_at、dedupe_key；重启恢复有界。
- 图片用本地字体排版成 PNG，长文自动分卡，文字和来源不能溢出；图片内容哈希参与审批。
- Windows 启停脚本、健康检查、日志轮转、备份与恢复说明。后台进程隐藏窗口。未接通账号前不要注册真实发帖常驻任务。
- 可选持久运行由本项目进程/Windows Task Scheduler 提供，不能依赖 Codex 对话一直开着。

## 来源选择注意
AIHOT 的开源引擎 MIT 与线上数据服务使用条款是两回事。线上 API 匿名可读，但外部商业产品、公开镜像/批量再分发等需书面许可。默认不把 AIHOT 全量摘要作为可发布素材库。优先直接追踪公开官方来源并独立写作；AIHOT 适配器如做，只用于明确允许的用途并保留溯源。
DeepSeek 现有 API 文档已提供独立 Search/Fetch API，可选做低预算补充，不能错误声称必须购买第二家搜索服务。

## 分阶段交付与实际验收
P0 本机闭环：来源导入 -> 去重 -> 结构化证据 -> 草稿 -> PNG -> 审批 -> 模拟发布 -> 重启恢复。先全部本地可跑。
P1 真实阅读与写作：接直接 RSS、DeepSeek，真实抓取和生成一份不发布的作品，保留来源与费用；没有真实配置则明确列出阻塞项。
P2 飞书与小红书：完成适配器和配置向导。先只读检查和手机审批演练；真实发帖必须展示最后作品，并等用户针对该作品确认。
P3 常驻与复盘：监督进程、恢复和提醒；小范围观察运行后再放开长期自动运营。

必测业务条件：
1. 同一事件重复拉取不重复入选；旧闻不冒充新热点。
2. 未批准不得调用 publisher；非本人消息无效；重复审批无重复发布。
3. 修改正文或图片后旧审批失效；过期审批无效。
4. 重启后保留待审批；publishing 未知结果不重发。
5. 429、超时、断网有界退避；模型预算超限暂停生成但审批仍可用。
6. 恶意来源内容不能改变权限；SSRF 地址被阻止。
7. mock 与 live 状态严格分开；缺少凭据不得报告外部联通成功。
8. PNG 能打开并人工检查；预览和最终发布内容一致。
