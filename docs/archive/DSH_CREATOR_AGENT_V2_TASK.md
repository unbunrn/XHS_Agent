## 2. 产品目标与完成定义

目标是“交付一份符合意图、事实表达诚实、正文与图片协同的作品”，不是完成来源证明手续，也不是无限优化分数。

必须支持：

1. owner 给选题/链接/写作角度 → 自主研究、创作、配图、检查 → 完整图文审批。
2. 既有定时任务 → 发现近期候选 → 模型结合账号定位/历史选择一个 → 进入同一创作循环。
3. owner 提出修改 → 理解本次意图和保留项 → 只补必要资料/修改必要部分 → 对照反馈验收 → 新版审批。
4. 用户问状态 → 返回简洁阶段、已有成果、真正阻塞；不把内部域名/搜索细节都抛给用户处理。

核心原则：模型选择下一动作，工具执行；程序控制权限、预算、版本与幂等；人决定是否发布。非必要不问用户：搜索失败先换查询、删非关键主张或调整可兼容角度；核心前提无法成立且无法忠实满足任务时才澄清。禁止偷偷改掉用户明确要求或把传闻写成事实。

本轮不做新平台、多账号、自动评论/私信、商业投放、完整数据增长优化、训练平台或 LoRA；课程微调实验以后独立安排。

## 3. 总体结构：一个主智能体 + 独立审稿调用

主智能体维护任务状态，观察工具结果，自主选择下一动作。审稿是独立上下文的专业角色，不是另一个无限循环的后台进程。两者可以使用同一运行时模型。不要为“多 Agent”额外引入调度框架、消息中间件或大量角色。

主循环伪代码：

    load/checkpoint task + active generation
    while not terminal and limits permit:
        observation = bounded context(state, evidence, artifact, feedback)
        decision = model.decide(observation, available tool schemas)
        validate decision and arguments
        reserve limits; execute authorized tool with idempotency key
        persist step + compact observation + artifact changes
        if eligible submit action: run deterministic submission checks
    checkpoint or return honest completion/clarification/deferred state

这只是运行机制，不固定 search→write→review 的顺序。例：图片拥挤可直接改布局，不必再次研究；事实矛盾可返回检索；非关键细节不足可删除该细节继续交稿。模型不得直接执行 SQL、shell、随意文件写入或直接发布。

关键分离：内部 candidate/artifact 保存允许不完整；“提交审批”才要求完整作品。不能复用会自动发审批的 create_draft 作为每次内部写作工具。把生成、渲染、持久化、最终审批提交拆为可复用函数，既有外部接口可暂用薄适配层。

## 4. 数据契约：先定义再实现

使用现有项目风格的 dataclass/类型与明确校验，不强制引入新框架。以下为语义契约，字段名可适配既有模型，交付报告列映射。

### CreativeBrief

- 任务来源 manual/scheduled/revision；账号/目标读者。
- 用户原始要求、必须满足项、不能改动项、可自主决定项。
- topic、research_mode、写作角度、成品目标。
- 对应 task_id、父任务、base_artifact_version、当前 generation。
- 只有明确用户命令可改变关键模式/目标；网页不能修改 brief。

### AgentDecision

- action：注册工具名或 submit/clarify/defer 等有限动作。
- args：按工具 schema 校验的参数。
- intent_summary：简短可审计说明，不保存/展示原始思维链。
- expected_result：本步要解决的具体缺口。
- referenced_material_ids、base_version。

一次决策最多一个有副作用动作；只读可小批量但每个调用独立计数。未知工具、越权参数、过时版本拒绝；重复非法调用达到阈值停止，不无限修 JSON。

### Material / ClaimAssessment

材料保留来源 URL、来源角色、原始发布时间/未知、抓取时间、正文或摘要类型、内容哈希、可引用片段与所属文章 ID。搜索摘要和聚合摘要永远不能伪装成原文。

主张分为 supported / attributed / inference / uncertain / contradicted；保存 claim_id、实际 material/片段引用、理由、适用表述和是否核心主张。身份可信度与事实支持度分开。禁止模型引用不存在的 ID；对于数字、日期、产品版本，检查与引用片段一致性。不能把“词面包含”直接等同整个论断得到证明。

### ArtifactVersion

不可变版本：标题、正文、标签、图片策划、最终图片文件及哈希、引用主张、revision_plan、review_result、brief_hash、parent_version。未完成作品也可保存，但状态必须 draft/incomplete，不能产生有效审批码。

### Review / RevisionPlan

审稿问题带 id、severity、具体位置、证据/反馈依据、建议动作；区别必须处理的事实/风险问题和可选表达优化。修订计划逐项对应用户意见，列 preserve/change/research_needed/image_changes/scope；每条意见有 addressed/not_applicable/unresolved 及依据，不用简单字符差异证明修改有效。

## 5. 工具面：复用底层能力，替换固定顺序

建议注册以下可组合工具，命名可调整：

- discover_topics：现有新闻/AIHot/来源发现，返回候选及时间信息。
- search：一次查询及实际搜索结果；不能默认只在官方 allowlist 发现。
- read_source：安全获取正文、缓存、发布时间和必要链接关系；返回结构化材料。
- inspect_claims：对指定主张进行一次证据支持/矛盾判断，可组合来源身份工具；不是全局阻塞开关。
- recall_context：历史作品、重复选题、账号定位和相关偏好；优先 SQLite 检索，不必上向量库。
- draft_artifact / revise_artifact：仅生成指定版本的内容或修改指定组件，不自动审批。
- render_images：读取经校验的图片策划并渲染，使用固定允许路径；禁止模型提交任意 Python/HTML 脚本执行。
- inspect_layout：尺寸、文字溢出、缺图、重复段落等程序检查。
- review_artifact：独立模型上下文审稿，以 brief、作品、实际材料、用户反馈为输入。
- submit_for_approval：完成校验后通过既有事务/outbox 创建审批与完整图文通知。
- ask_owner：仅必要澄清，保存原因和选项；无关过程错误优先自行解决。

工具注册表包含参数 schema、权限、是否读写、幂等方式、超时与计费类别。复用 SSRF/HTTP/预算预约，不另写绕过安全的抓取实现。身份关系可以作为材料质量信号，但新来源不是天然禁止写作。

## 6. 来源政策：解决“卡在域名”的根因

取消新创作路径“所有正文 source_verified=true 才能写”的全局规则。允许官方、论文、文档、媒体、社区和聚合材料按各自角色参与。

- 明确且有依据的事实正常写。
- 厂商宣称必须归因，不把宣传变独立评测结论。
- 社区观点只作为观点/案例，不推定具有代表性。
- 聚合摘要可用于发现、带明确归因的有限概述，不支撑摘要之外的细节、独立性能结论或精确数字。
- 推论解释依据并用相应语气；争议/未证实内容标明，非关键内容可删除。
- 核心前提被证伪、证据冲突无法解决时，不生成确定性发布新闻；在不违背用户目标时调整角度，否则只问一次关键澄清。

程序硬性约束：材料/引用 ID 真实、正文与摘要不混淆、来源不伪装、已知矛盾不被无声忽略、重要数字/日期不可凭空编造、敏感秘密不输出；内容与违规判断仍不保证绝对正确，审稿是辅助而非法律合规认证。

旧 verified 字段保留历史语义，不把 secondary/unknown 全部改 true。新增 submission eligibility 必须贯穿写稿验证、审稿、审批、发布；否则上游允许媒体，下游又按旧 source_verified 一律拒绝，仍是旧问题。历史稿件用明确 legacy policy version 解释，不批量重写历史证据/审批。

news 保持实际发布时间策略；analysis 允许诚实标注的旧材料。搜索发现日期与最终表述时效分开。不得把材料未知日期改为今天。

## 7. 图文共同创作，不把正文装进图片

每篇由模型自主设计图片数量、信息分工与视觉结构，在平台尺寸/资源上限内执行。不要规定每篇“封面+三点+总结”，也不要求每张固定字数。可用图解、对比、步骤、案例、关键证据卡等基本绘图能力；这些是渲染原语，不是强制文章模板。

图片策划至少写明 purpose、展示信息、与正文的关系、内容节点、视觉层级与来源；正文负责论证/叙述，图片补充结构/对比/示例。必要标题或术语可重复，不把低重复率当唯一质量指标。

复用当前 Pillow/渲染层；需要时扩展安全的 declarative scene/schema。工具检测溢出/裁切/字体/尺寸、图片重复、正文整段复制，失败回传位置与原因供主模型调整。若无可用视觉模型，标记 visual_review=not_available；绝不把文本模型读 storyboard 冒称真实图片视觉验收。无需购买或强制接入图像生成模型。

改标题不重做所有配图；“保留第二张图”必须用图片资产 ID/哈希表达，修订不可意外替换。完整审批材料必须来自同一 artifact_version。

## 8. 人类反馈与记忆

用户批准当前版本才允许既有发布路径工作。收到修改指令后：立即使相关旧版本不可发布 → 提取 RevisionPlan → 按需查资料/改组件 → 独立核对反馈落实 → 提交新版本。每次修订保留前后版本和逐条落实说明，用户只看到简短改动摘要与完整新作品。

## 9. 持久化、并发与资源控制

复用现有 jobs/租约/outbox，不新建第二套调度。可追加 agent_runs、agent_steps、artifact_versions、preference_memory（已有表足够则复用），列出 ER/字段说明而非机械照抄表名。

- 每个 run 有 account_id、origin/manual/scheduled/revision、generation、状态、计数、policy_version、checkpoint。
- 每步先持久化 action_id，副作用幂等；提交审批唯一键至少包含 run/generation/artifact_hash。
- 崩溃恢复从 checkpoint 继续，计数不重置，不重复通知/渲染覆盖/审批。供应商请求结果未知时保留预算占用；只读重试仍计费，不能声称网络操作严格 exactly-once。
- 内部版本只增版本数，不反复消耗“人工首稿配额”；自动/手动来源标签不因修订丢失。
- 定时同一时间窗口只能生成一次选题任务；手动和定时走同一 runner。先查近期历史避免重复，但不固定“热门词必须选”。
- 线程运行中禁止用户控制命令无限排队多个相同 run；状态更新、失效旧审批、入队新任务同事务完成。

建议新配置命名空间 creator_agent，避免误覆盖已有 agent 开关：enabled、max_steps=8、max_revision_steps=6、max_review_cycles=2、max_searches=5、max_physical_fetches=6、max_model_calls=14、max_invalid_decisions=2、max_no_progress_steps=2、max_run_seconds=600。数值是可调整初始值；模型决策/写作/审稿/JSON 修复等物理模型请求全部计入上限，传输重试也计入实际调用及全局账本。工具内部不能藏额外循环。

遇到预算不足保存并 deferred；权限/安全边界不降级。步骤/质量循环达到上限时，若已有作品无未解决关键问题，提交并简短说明次要局限；核心事实不成立则保留内部成果并澄清/说明。不要仅因审稿还有 stylistic suggestion 就抛 DraftError 丢弃成果。相同工具与相同输入连续无新结果则避免重复，改变动作或停止。

## 10. 按当前 DSH 模型安排开发，而不是硬改运行时模型

`deepseek v4.1flash 1017 / max` 是用户选择的 Harness 开发模型。不得将这个显示名称未经验证写成 bot HTTP API model ID，也不能猜测 API reasoning_effort=max 或多模态/tool-calling 支持。开发模型与线上运营模型是两层配置。

优先沿用 complete_json，增加 agent_decide/revision_plan/agent_review 等 purpose；用程序 dispatch JSON action 实现工具调用，不要求服务商原生 function calling。运行时可按 purpose 配置输出上限/思考选项，但先复用已确认支持的参数；未验证字段不发送。错误、truncated/finish_reason、无效 JSON 有界处理，不用模糊文本解析执行工具。FakeLLM 必须可按观察与测试脚本产生不同动作，不能永远固定 search→draft→submit。

为减少 Harness 上下文和 max 推理成本：

1. 先读本文件，再按依赖读模块，不一次吞整个仓库；用 rg 定位。
2. 每阶段先列接口和失败用例，再做一个可运行纵向切片；不在代码未接线时宣称完成。
3. 用 `docs/delivery/CREATOR_AGENT_V2_PROGRESS.md` 保存事实检查点：已改文件、通过命令、剩余阻塞、下一步。上下文续接只读此文件和当前相关模块。
4. 一个开发会话顺序完成，不启动多代理、不逐阶段等待 Codex。避免频繁全套测试，阶段测受影响范围，最终一次全套；有新修复按影响补跑。
5. 使用当前实际可用的 Harness 设置，不升级/修改安装。`docs/HARNESS_CONTROL.md` 是历史说明，里面旧 CLI 版本和参数不是当前事实；用户在桌面执行即可。若用 CLI，只传单行“阅读任务文件并执行”，完整内容放文件，避免 Windows 多行截断。

## 11. 模块落点与删除策略

建议新增小包 `bot/services/creator_agent/`，职责可分 contracts、runner、tools、context、claims、feedback；文件按实际需要合并，不为每个名词造文件。prompt 放单一可维护位置，遵循项目现有风格。topics 保留飞书路由/命令与任务编排，worker 只分发，drafts 提供作品存储/渲染/审批提交能力。

迁移顺序：先包裹可复用底层工具 → 新循环跑通 → 手动/定时/修订全部接入 → 测试与回放确认 → 删除不再引用的旧编排。

可替换/清理候选（不是不经检查直接删）：

- research_plan/research_orchestrator/adaptive_research 中只为旧固定步骤服务的编排与关键词补救。
- topics 中 model_source_domains、固定 rescue/重复源判断与多个相互叠加的预算循环。
- drafts 中独立旧 critic loop：其有用的审稿 schema/函数迁入统一 review 工具，不能新旧两层都重写一次。
- source_identity 保留可解释来源判断与作用域工具，移除其在新路径的全局 verified 门槛；被旧数据或接口引用时保留薄兼容层。
- agent_eval 扩充而不是另写第二个指标系统；aihot 保留发现适配器，不保留特殊绕过事实策略的暗门。

不得无证据删除 approvals、publish、publication_results、reconcile_readonly、预算/网络安全、外部适配器和历史迁移。先 rg 查 import/入口/文档、确认替代能力和测试覆盖，再删；交付 `cleanup-manifest.md` 写删除路径、原因、替代位置、兼容影响。旧测试若约束已改变应改为新契约，并写说明；重复实现测试可合并，权限/幂等/来源不伪装等测试保留。

不要求永久维护两套生产链路。过渡期开关明确唯一活动路径，默认保守不自动改变 live；保留旧 baseline 的脱敏评估记录/可恢复源码快照即可，最终交付标注待移除兼容层。不要在主目录存大份源码压缩包。

## 12. 连续实施计划

### A：接口、持久化与真实决策循环

定义契约/计数/checkpoint、工具注册表和离线 ScriptedLLM。手动请求至少实现两条不同路径：资料充足直接创作；证据不足自主补查后创作。拒绝“固定顺序写死、模型只填参数”的伪循环。

### B：材料/主张策略与图文生成

把当前搜索、读正文、AIHot、来源分析封装工具；移除新路径全局域名门槛；接入可保存内部版本的图文工具、布局检查和独立审稿。让删非关键无证据说法也是合法完成动作。

### C：修订、偏好与三入口统一

手动/定时/用户修订接同一循环。落实保留项、图文局部改动、并发 generation、审批失效、偏好作用域。飞书用既有命令向后兼容，不新增繁琐操作步骤。

### D：清理、恢复验证、评估与交付

删确认冗余路径，补迁移与崩溃回归，维护配置、文档和课程展示。以上阶段连续完成不逐阶段等批准；无法完成的点明确记录，不用 TODO 冒充完成。

## 13. 验收矩阵：必须有业务断言

至少覆盖以下场景，可拆多个测试：

1. 同一主循环根据工具结果走不同动作序列，不是固定 pipeline；任务记录可回放决策摘要。
2. 中文搜索无结果后模型更换查询；资料够用后不耗尽所有搜索额度。
3. 有可引用媒体正文而非官方域名，仍能形成诚实归因图文；不得把媒体标 official。
4. 某数字无依据，删数字或降为不确定性后仍可交稿；核心发布前提被否定则不能生成确定性发布稿。
5. 聚合摘要/搜索摘要不升级成原文；虚构引用 ID/未知图片资产拒绝；网页要求改预算/直接发布无效。
6. 正文与图片分工明确，布局检查失败能修图；没有视觉能力时状态明确，不伪造检查结果。
7. 用户“少讲技术、解释影响、保留第二张图”逐项落实；第二张图哈希保持；只改标题不重写全部。
8. 审稿指出证据缺口 → 能研究再修订；指出措辞偏好 → 仅改写；次要建议到上限不丢弃安全成品。
9. 新反馈到达后旧 generation 不能提交审批；旧批准不能发布新图文；publishing/unknown 不重复提交。
10. 崩溃于工具返回/作品保存/通知入队附近，恢复不重复审批/通知；预算计数不重置。
11. 手动首稿配额与内部修订分离；自动来源不被修订改成手动；定时任务不重复选题入队。
12. 偏好仅作用于正确账号与场景，删除后失效；本次意见不强行成为永久偏好。
13. 所有上限覆盖工具隐藏请求/重试；预算不足保存可恢复成果，正确 deferred；非法工具和无进展循环有界退出。
14. 现有发布确认、unknown、对账、配额、安全和飞书 owner 验证不退化。
15. 追加迁移在合成旧库保留旧草稿/审批/通知/任务，重复 init 幂等，integrity_check=ok；旧待办的兼容策略明确。

至少包含从飞书入站处理→job→runner→图文版本→outbox审批的全链路假响应测试，不能只测内部函数。scheduler 路径同样要测。FakeNotifier/mock publisher 结果不得称真实发送/发布。

## 14. 课程实验与诚实展示

复用 agent_eval，提供约 24–30 个固定场景清单，覆盖普通新闻、跨语言、非官方资料、核心前提错误、旧文、修改和图文分工。至少比较固定工作流 baseline、V2 无偏好记忆、V2 有记忆。统一模型、工具数据快照和资源上限，报告成功率、事实支持/归因、修改落实、人工盲评、费用、耗时及失败类别；关注 trade-off，不保证 V2 所有指标更好。

离线轨迹/假模型测试只能证明工程机制，不能证明真实 LLM 内容质量。交付 live eval 命令支持 dry-run、案例上限、总费用上限、无发布/无通知模式；本轮不执行收费评测，不伪造分数。偏好实验训练/开发示例与测试主题分开，避免记住答案。保存决策摘要/工具输入输出引用，不收集或公开思维链、秘密和原始私聊。
